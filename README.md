## 三、控制结构
```
DR16 遥控器
   │  通道：ch_lv(vx) / ch_lh(vy) / ch_lu(ω)  拨杆：sw_r / sw_l
   ▼
档位判断（sw_r）        0 = 停止，1 = 正常驱动，2 = 其他动作
   ▼
死区处理 → 目标速度（应用方向系数 DIR_VX / DIR_VY / DIR_OMEGA）
   ▼
四轮逆解（全向轮）
   v1 = ( vx + vy − ω) / R
   v2 = ( vx − vy + ω) / R
   v3 = ( vx + vy + ω) / R
   v4 = ( vx − vy − ω) / R
   ▼
每轮速度环 P（SPEED_KP = 1.0，输出限幅 MAX_TORQUE = 0.8 N·m）
   · 输出死区 0.02 N·m，避免零位抖动
   · 低速保持：指令速度低于 0.5 rad/s 时按目标方向给一点保持力矩
   ▼
功率限制：四个力矩统一乘 power_scale（0~1）
   ▼
CAN 0x200 一帧下发四轮
```
**设计要点**：功率限制只做**统一缩放**，四个轮子的力矩比例保持不变，所以限功率不会改变底盘的转向/运动方向。

## 四、功率预测模型
### 模型
```
P_预测 = Σ(τ_i · ω_i)              机械功率（再生为负）
       + 0.25 · |Σ(τ_i · ω_i)|     传动 + 电调效率损失
       + K1 · Σ τ_i²               铜损（正比于力矩平方）
       + K2 · Σ ω_i²               铁损
       + K3                        静态损耗
```
参数：`K1 = 2.80`、`K2 = 0.009`、`K3 = 4.0 W`、效率系数 `0.25`。
### 假设
1. 力矩与电流近似线性（τ = Kt·I），用 τ 代表电流
2. 铜损按力矩平方建模（I²R）
3. 四轮损耗可加，忽略轮间耦合与单轮差异
4. 效率损失与功率大小近似成正比
5. 静态模型，不建模电流环动态
6. 用**指令力矩**而非实际力矩（指令瞬时已知）
### 误差来源
| 来源 | 影响 |
|---|---|
| 拟合数据只覆盖到约 62 W，限幅点在 72~80 W，属外推 | 高功率段偏差大 |
| 指令力矩 ≠ 实际力矩（电流环延迟、电调死区） | 瞬态低估 |
| 电池电压跌落 → 同样力矩下电流更大 | 电量低时低估 |
| 绕组升温 → 电阻上升 | 长时间运行后低估 |
| 再生制动效率不确定 | 减速段误差大 |
| 摩擦/滚阻未独立建模（折进 K1、K3） | 低速大扭矩工况偏差 |
| 功率计有采样周期与滤波，且经 CAN 传输 | 反馈滞后 |
**结论**：误差是**系统性、慢变**的（主要来自拟合区间 + 温度/电压），因此用**慢速乘性修正**补偿，而不是快速积分。

## 五、限功率控制策略
三层结构。
### 第一层：预测 + 统一缩放搜索
把期望的四轮力矩代入模型。若预测功率超预算，找一个统一系数 k：
```
P(k) = K1·Στ² · k²  +  Σ(τω) · k  +  (效率项 + K3)
        ↑二次（铜损）    ↑一次（机械）    ↑与 k 无关
```
因为功率对 k 是**二次**函数，不能按比例线性缩放，所以用**二分搜索**（24 步）求满足预算的最大 k。当机械功率为负（再生）时曲线存在极小值，先求极小点再搜索，避免跳到错误解。
### 第二层：慢速乘性修正（bias）
用功率计的**滤波值**与预算比较，缓慢调整乘性系数：
```
0.3 s 一阶低通滤波
超预算     → bias −= 5e-5 × 误差
低于 2 W 以上 → bias += 2e-5 × (|误差| − 2)
bias 限幅 [0.6, 1.3]
最终预算 = (80 − 8) W × bias − 前瞻预留
```
选乘性而非加性：模型误差主要是比例误差（拟合区间、效率、电压都近似按比例影响），乘性修正物理意义更合理，且在不同功率水平下都成立。
### 第三层：前瞻预留
按期望功率的**上升速率**预留余量：
```
reserve = clamp(上升速率 × 0.05 s, 0, 15 W)
```
预测无延迟，但实际功率有延迟（电调、机械），冲刺时提前让出余量可抑制超调。
### 瞬态保护
除主模型外还有一层按实测功率的快速保护（`TRANS_GUARD_NEAR_W = 78` / 恢复 76 W），只用于抑制突变尖峰。
### 一条原则
**功率计的原始读数从不修改**。它只作为模型修正的输入与遥测输出，保证测量数据可信。

## 六、功率限制的参数与判读
```cpp
CHASSIS_POWER_LIMIT_W   = 80.0f   // 硬性上限
POWER_LIMIT_MARGIN_W    = 8.0f    // 裕量 → 预算 72 W
POWER_BIAS_MIN / MAX    = 0.6 / 1.3
POWER_BIAS_FILTER_S     = 0.3f
POWER_RESERVE_LEAD_S    = 0.05f
POWER_RESERVE_MAX_W     = 15.0f
POWER_METER_TIMEOUT_MS  = 200U    // 超时则不再参与修正
```
预期的实测表现：**均值贴着 72~80 W 跑，偶有小幅超出**。

## 七、串口调试
USART1，**921600** 8N1。协议：`AA BB` + 长度字节 + 若干 little-endian float。
由 `plot_task.cpp` 顶部的 `PLOT_MODE` 与 `CHASSIS_CONTROL_DIAGNOSTICS` 选择模式：
| 模式 | 通道数 | 内容 |
|---|---|---|
| `CHASSIS_CONTROL_DIAGNOSTICS = false` | **2** | 通道 1 = 80 W 参考线，通道 2 = **功率计实测功率** |
| `= true`，`PLOT_MODE = 0` | **7** | DBUS 接收诊断（帧率 / 事件 / 帧长 / DMA 剩余 / 错误） |
| `= true`，`PLOT_MODE = 1` | **9** | 链路快照（拨杆 / 摇杆 / 反馈掩码 / 限幅系数 / 单轮力矩）|
**接串口前先确认当前模式**，否则通道数不匹配会看起来"没有数据"。

## 九、常见问题排查
| 现象 | 优先怀疑 | 怎么查 |
|---|---|---|
| 遥控器无反应 | DBUS 接收 | 切到 `PLOT_MODE = 0`，看第 1 通道是否有整帧（正常约 1 帧/20 ms）|
| 收到信号但不动 | 拨杆档位不对 | 切到 `PLOT_MODE = 1`，看 `sw_r` 是否为 1 |
| 电机不动 | CAN 收发 | 看反馈掩码（15 = 四轮都有反馈）|
| 功率一直被限制 | 功率计是否在线 | 功率计超时 200 ms 后不再参与修正；看实测通道是否有值 |
| 功率超调大 | 裕量偏小 | 提高 `POWER_LIMIT_MARGIN_W` |
| 功率利用不足、均值偏低 | bias 收敛慢 | 提高 `POWER_BIAS_UP_PER_W` |
| 一上电就满功率 | 零点/方向系数错 | 检查 `DIR_VX / DIR_VY / DIR_OMEGA` 与四个 `DIR_M_*` |

## 十、约定
- 功率模型与限制参数统一写在 `control_constants.hpp`，不要在模块内写死
- 修改 `POWER_K1 / K2 / K3` 后必须在实机上验证均值与峰值，光看仿真不准（标定区间不足）
- 功率计读数不可修改，它同时用于模型修正与遥测
- `build/` 已在 `.gitignore` 中排除，提交前确认未被跟踪
- 调参一次只改一个参数并立即实机验证，否则无法定位原因
